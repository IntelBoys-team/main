# PixelForge — Архитектура (для разработчиков)

Документ описывает **как устроен проект, как текут данные, как работают потоки**
и что менять для типовых задач. После прочтения не нужно читать исходники целиком.

Подробный справочник по каждой функции — в [API.md](API.md).

---

## 1. Что это

Пакетный конвертер изображений: PNG / JPEG / BMP → **WebP** или **JPEG**,
с ресайзом (с сохранением пропорций), пакетной обработкой в пуле потоков,
Drag-and-Drop в GUI (PyQt6), валидацией содержимого архивов по Magic Numbers.

## 2. Слои (3-Tier)

```
┌──────────────────────────────────────────────────────────────┐
│ PRESENTATION (UI)                                            │
│   ui_pyqt.py    — активный UI на PyQt6 (запускается из main) │
│   ui_app.py     — legacy-вариант на Tkinter/CTk (НЕ используется)│
└───────────────▲──────────────────────────────────────────────┘
                │ вызовы функций + Qt-сигналы (из фоновых потоков → GUI-поток)
┌───────────────┴──────────────────────────────────────────────┐
│ SERVICE                                                      │
│   thread_manager.py    — пул потоков, очередь, счётчик       │
│   archive_validator.py — валидация архивов/файлов, распаковка│
│   image_core.py        — ресэмплинг + конвертация (Pillow)   │
└───────────────▲──────────────────────────────────────────────┘
                │
┌───────────────┴──────────────────────────────────────────────┐
│ DATA / STORAGE                                               │
│   config_manager.py    — config.json + каталог .cache_processing/│
└──────────────────────────────────────────────────────────────┘
```

Правило из ТЗ (п.1.4): **никаких алгоритмов валидации/сжатия в UI**.
UI только собирает настройки, вызывает сервисный слой и рисует состояние.

## 3. Точки входа

| Файл | Роль |
|---|---|
| `main.py` | Единственная точка входа. Добавляет каталог проекта в `sys.path`, вызывает `ui_pyqt.run()`. При `ImportError` печатает подсказку про `pip install -r requirements.txt`. |
| `ui_pyqt.py::run()` | Создаёт `QApplication`, окно `ImageConverterWindow`, возвращает код выхода `app.exec()`. |
| `ui_app.py` | Резервный UI (Tkinter + CustomTkinter + tkinterdnd2). Не подключён к `main.py`; оставлен как альтернатива/архив. |

Запуск: `python main.py`.

## 4. Жизненный цикл сценария (как всё работает по шагам)

### Шаг 0. Старт приложения
`main()` → `ui_pyqt.run()` → конструктор `ImageConverterWindow`:
`ConfigManager()` подгружает `config.json` (или берёт дефолты),
`ThreadManager()` считает `max_workers = clamp(os.cpu_count(), 2, 16)`,
виджеты заполняются из конфига, кнопка «Старт» заблокирована.

### Шаг 1. Выбор источника (Drag&Drop / «Обзор»)
Источником может быть **архив** (`.zip`, `.rar`, `.7z`), **папка** или **одиночный файл**.
Любой путь проходит через `ImageConverterWindow.load_source(path)`:

1. `load_source` эмитит `sig_busy(True)` (настройки заморожены, прогресс-бар — бесконечная анимация)
   и запускает **daemon-поток** `_validate_bg(path)` — валидация не должна блокировать GUI.
2. `_validate_bg` в фоне ветвится по типу источника:

| Тип | Что происходит | Кэш? |
|---|---|---|
| Архив | `ConfigManager.clear_cache()` → `validate_and_extract(archive, cache_dir)`: потоковое чтение оглавления, проверка **расширения + Magic Numbers** каждого файла, распаковка в кэш, повторная проверка сигнатур на диске | да, `source_from_cache=True` |
| Папка | `collect_from_folder()` — рекурсивный поиск `.png/.jpg/.jpeg/.bmp` (неподдерживаемые пропускаются) | нет |
| Файл | `validate_single_image()` — расширение + сигнатура | нет |

3. Успех: `source_files` заполнен, кнопка «Старт» разблокирована, статус «Валидация успешна».
4. Ошибка (`ValidationError` или любая другая): лог, красная рамка зоны дропа на 600 мс,
   модальное окно, `source_files` очищен, кэш стёрт, «Старт» заблокирован.

> **Важно:** архив распаковывается **один раз** на цикл. После конвертации кэш стирается,
> поэтому источнику-архиву нужна новая валидация (перетащить заново). Для папки/файла
> можно жать «Старт» многократно.

### Шаг 2. Конвертация
`on_start()`:
1. Собирает `kwargs` из виджетов (формат, качество, ресайз, интерполяция) и путь назначения
   (`_output_dir()`: явная папка из конфига → `<родитель первого файла>/Converted` → `./Converted`).
2. Ставит `working=True`, замораживает UI, эмитит `sig_progress(0, total)`.
3. Запускает daemon-поток `_convert_bg(files, dst, kwargs)`, который вызывает блокирующий
   `ThreadManager.start(...)` с четырьмя колбэками:
   - `on_progress(done, total)` → `sig_progress` → обновление прогресс-бара и счётчика
     «Обработано: X из Y файлов (Z% объектов)»;
   - `on_ok(src, dst)` → строка `OK  name -> name` в журнале;
   - `on_error(src, msg)` → строка `ОШИБКА name: msg` (битый файл **не** роняет пакет);
   - `on_finished(done, total)` → журнал «Готово», статус, **звуковой сигнал** (`QApplication.beep`).

`ThreadManager.start()` внутри:
- `reset()` (сбрасывает флаг прерывания, счётчики, очередь),
- кладёт все файлы в потокобезопасную FIFO `queue.Queue`,
- поднимает `ThreadPoolExecutor(max_workers)` и `max_workers` «воркеров»-функций;
  каждый воркер циклически забирает файл из очереди и вызывает `image_core.convert_image`,
  инкрементирует общий счётчик **под `threading.Lock` (Mutex)**,
- дожидается всех future (`fu.result()`), затем `shutdown(wait=True)`.

Остановка «Прервать»: `on_abort()` → `ThreadManager.abort()`:
флаг `threading.Event`, мгновенная очистка очереди, `shutdown(wait=False, cancel_futures=True)`.

### Шаг 3. Финализация
`_convert_bg` в `finally` всегда:
- стирает кэш (`ConfigManager.clear_cache`);
- если источник был из кэша — сбрасывает `source_files` (требуется повторная валидация);
- снимает `working` и `sig_busy(False)` (настройки размораживаются, поля W/H возвращаются
  в состояние чекбокса «Изменить разрешение»);
- разблокирует «Старт», если ещё есть файлы.

## 5. Модель потоков (самое важное при правках)

```
GUI-поток (Qt)                     Фоновый поток валидации        Пул рабочих потоков
──────────────                     ──────────────────────         ──────────────────
load_source() ── threading.Thread ─▶ _validate_bg()  ─────────┐
                                  │   (архив/папка/файл)      │
on_start()   ── threading.Thread ─▶ _convert_bg()             │
                                       │                      │
                                       ▼                      ▼
                                  ThreadManager.start() ──▶ worker() × N
                                       │   convert_image() в каждом воркере
                                       ▼
                                  колбэки on_progress/on_ok/on_error
                                       │   (выполняются В worker-потоках!)
                                       ▼
                                  sig_*.emit()  ── Qt-сигналы ──▶ слоты в GUI-потоке
```

**Правило потокобезопасности:** из фоновых потоков **нельзя** напрямую трогать виджеты.
Только эмитить `pyqtSignal` класса `ImageConverterWindow`; сигналы автоматически
доставляются в GUI-поток (соединения установлены в `_connect_signals`).

Колбэки `ThreadManager` (`on_progress`, `on_ok`, `on_error`, `on_finished`) вызываются
**из рабочих потоков** — в `ui_pyqt.py` они лишь эмитят сигналы, и это единственно верный паттерн.

Ограничения:
- `ThreadManager.start()` **блокирующий** — поэтому он и вызывается из фонового потока `_convert_bg`.
- Один `ThreadManager` на окно (`self.tm`), повторный `start()` безопасен — он сам делает `reset()`.
- `abort()` не отменяет файл, который уже конвертируется прямо сейчас (он доработает текущий файл);
  отменяются только ещё не начатые.

## 6. Хранилище

| Что | Где | Управление |
|---|---|---|
| Настройки | `%APPDATA%/PixelForge/config.json` (на не-Windows — `./config.json`) | `ConfigManager`: `load()` нормализует значения (quality 10–100, допустимые формат/интерполяция), `update()` пишет на диск сразу |
| Кэш распаковки | `%TEMP%/PixelForge/.cache_processing/` | `get_cache_dir()`; `ConfigManager.clear_cache()` — `shutil.rmtree(ignore_errors=True)`; стирается перед распаковкой, после конвертации и при любой ошибке |

Ключи конфига и дефолты — в `config_manager.DEFAULTS` (добавляя новую настройку,
правьте **там**: она автоматически подхватится при чтении и не отвалится валидацией).

## 7. Валидация (безопасность входных данных)

Проверка двухуровневая, для каждого файла внутри архива:
1. **Расширение** входит в `SUPPORTED_EXTS = {.png, .jpg, .jpeg, .bmp}`;
2. **Magic Number** первых 4 байт совпадает с одной из сигнатур:
   PNG `\x89PNG`, JPEG `\xFF\xD8\xFF`, BMP `BM`.

Любой «чужой» файл (в т.ч. переименованный) → `ValidationError` со стандартным текстом
«Ошибка валидации: архив содержит неподдерживаемые типы данных. Конвертация невозможна» —
UI показывает модальное окно, красную рамку, кэш стирается.

Особенности:
- оглавление читается **потоково** (`zipfile.infolist()`, `py7zr.getnames()`, `rarfile.infolist()`),
  без полной распаковки — ТЗ п.2.3;
- `.7z`/`.rar` — опциональные зависимости (`py7zr`, `rarfile`), импортируются лениво;
  если библиотеки нет — `ValidationError` с просьбой установить;
- после распаковки сигнатуры **проверяются повторно на диске** (`validate_and_extract`, финальный цикл);
- в сообщение попадает максимум 5 проблемных имён (чтобы не заливать окно текстом).

## 8. Конвертация изображений (нюансы `image_core`)

- Ресайз: `compute_target_size()` считает целевой размер. При `keep_aspect=True` и заданных
  **двух** сторонах берётся `min(scale_w, scale_h)` (изображение вписывается в бокс, а не растягивается).
- Коллизии имён: если `name.webp` уже существует — `name_1.webp`, `name_2.webp`, …
- WebP: `method=6` (максимальное сжатие, медленнее), палитра `P` → `RGBA` (сохраняется прозрачность).
- JPEG: альфа-канала нет — `RGBA/LA/PA/P` конвертируются в `RGB` **с заливкой белого фона**
  через маску альфа-канала (прозрачные области → белые, а не чёрные).
- `quality` нормализуется в `[10, 100]`; неизвестная интерполяция молча → Lanczos.
- Битый файл: `Image.open()`/`im.load()` бросает исключение → ловится в `ThreadManager`
  и уходит в `on_error`, пакетная обработка продолжается.

## 9. Как это расширять — краткие рецепты

**Новый формат вывода (например, PNG):**
1. `image_core.OUTPUT_EXT["PNG"] = ".png"`, в `convert_image` — ветка сохранения,
   в `compute_target_size`/нормализации — допустимое значение;
2. `config_manager.DEFAULTS` и нормализация в `ConfigManager.load()`;
3. `ui_pyqt.py` — пункт в `fmt_box` (`.addItems([...])`) и `INTERP_ITEMS`, если нужна своя интерполяция.

**Новый тип архива (например, TAR):**
1. `archive_validator.ARCHIVE_EXTS.add(".tar")`;
2. Новая ветка в `validate_and_extract()` (паттерн — копировать ветку `.zip`: имена → валидация → распаковка);
3. Фильтр в `QFileDialog` в `on_browse_source()`.

**Новый тип входного изображения (например, TIFF):**
1. `SUPPORTED_EXTS.add(".tiff")`;
2. Сигнатура + ветка в `detect_image_kind()`;
3. Убедиться, что Pillow сохраняет/читает формат.

**Новая настройка в конфиге:** ключ и дефолт в `DEFAULTS` → виджет в `_build()`
→ чтение в `_apply_config_to_widgets()` → запись в `_persist()` → проброс в `kwargs` в `on_start()`.

## 10. Конвенции проекта

- Python 3.11+, `from __future__ import annotations` в каждом модуле (сигнатуры с `X | Y`).
- `pathlib.Path` вместо строковых путей на границах модулей.
- Аннотации типов у публичных функций.
- Русскоязычные docstring'и с упоминанием пункта ТЗ там, где решение продиктовано ТЗ.
- Исключения сервисного слоя — `ValidationError` (единый тип для всех ошибок валидации).
- UI-константы палитры — верхним регистром в начале модуля (`BG`, `PANEL`, `ACCENT`, `ERROR`).

## 11. Известные особенности / на что смотреть

- `ui_app.py` не используется `main.py` — при правках UI правьте `ui_pyqt.py`.
- `ThreadManager._done/_total` читаются из GUI-потока без лока — на практике безопасно,
  т.к. чтение атомарно в CPython, но помните об этом при рефакторинге.
- `config_manager.get()` возвращает `default` только если он не `None` — поведение хитрое,
  при сомнениях используйте `cfg.get(key, fallback)` с явным fallback или `cfg.data`.
- После завершения цикла с архивом `source_files` очищается — кнопка «Старт» снова заблокирована
  до новой перетаскивки архива (это ожидаемое поведение, следствие удаления кэша).
